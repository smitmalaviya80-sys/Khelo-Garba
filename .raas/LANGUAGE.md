# PlayGarba language system

Use this whenever a change affects user-facing copy, UI labels, metadata presentation, onboarding, docs, SEO text, social preview text or public issue-derived content.

## Voice

PlayGarba should sound like someone who knows the music and respects the listener.

Write:

- direct;
- concise;
- culturally literate;
- useful before promotional;
- specific when evidence exists;
- plain about uncertainty when evidence does not exist.

Avoid generic product marketing language, AI filler and festival clichés.

## Default style

- Use short, natural sentences.
- Prefer active voice.
- Use sentence case.
- Keep functional UI labels plain and immediately understandable.
- Preserve artist names, release titles and canonical transliterations exactly as the data defines them unless the task is an evidence-backed correction.
- Use Gujarati/Garba terms when they are the correct term, not as decorative flavour.
- Do not over-explain obvious controls.
- Do not turn metadata into sales copy.

## Words and patterns to avoid

Avoid phrases such as:

- `vibrant tapestry`
- `rich cultural heritage` when used as empty filler
- `immerse yourself`
- `ultimate destination`
- `one-stop destination`
- `unforgettable journey`
- `experience the magic`
- `celebrate the spirit` unless the surrounding copy says something concrete
- unsupported superlatives such as `best`, `largest`, `complete`, `definitive` or `#1`

Do not write as if every screen is a marketing landing page.

## Music and cultural accuracy

Do not flatten distinct terms for convenience.

- Garba, Raas, Dandiya, Sanedo, Dakla, Hinch, folk, devotional material, nonstop sets and live performances can overlap, but they are not synonyms.
- Use the canonical taxonomy and release evidence rather than assuming classification from a title.
- Do not invent the meaning, origin, story or devotional context of a song or release.
- Do not invent Gujarati translations or transliterations. If a translation is useful but unsupported, omit it or create a research issue.
- Do not call an artist, song, release or performance `iconic`, `legendary`, `classic`, `traditional` or `folk` unless the context or evidence supports that description.

## Metadata presentation

Metadata should be factual and calm.

Good patterns:

- `From Ramzat 2`
- `Nonstop Garba · chapter 4`
- `YouTube recording`
- `Release year unknown`
- `Track list not yet verified`

Bad patterns:

- invented stories to fill an empty description;
- guessed release years;
- generated artist biographies with no source;
- calling a provider recording official when it has not been verified as such;
- hiding uncertainty behind polished prose.

## UI labels

Prefer familiar product language for controls: `Play`, `Pause`, `Next`, `Previous`, `Explore`, `Search`, `Install`, `Open in YouTube`, `Back to player`.

Do not translate functional labels merely to make the interface feel more Gujarati unless a localisation issue explicitly defines that behaviour.

Use culturally specific language in content and metadata where it is meaningful, not where it makes controls harder to understand.

## Descriptions and SEO

Descriptions should answer a real user question or add source-backed context. They should not exist merely to make a page longer.

For artist/release/catalogue descriptions:

1. prefer verified factual context;
2. state what the listener can find or hear;
3. preserve uncertainty;
4. avoid duplicated boilerplate across pages;
5. do not create thin pages solely for search volume.

For SEO/AEO/GEO work, useful structure and truthful catalogue context outrank keyword repetition.

## Error and unavailable states

Be specific and non-blaming.

Prefer:

- `This recording is not available yet.`
- `No verified YouTube route yet.`
- `We could not verify this track list.`
- `Try another release.`

Avoid pretending a failure is intentional if it is a bug.

## Copy review checklist

Before shipping user-facing text, ask:

- Is every factual claim supported?
- Did I preserve canonical names and spellings?
- Did I use the right cultural/music term?
- Is this shorter without losing meaning?
- Does it sound like product copy rather than generated marketing prose?
- Does the CTA name the action the user will take?
- Does any uncertainty need to remain visible?
