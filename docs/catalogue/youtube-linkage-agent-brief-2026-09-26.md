## Rules (non-negotiable)

1. **YouTube only.** No Spotify, Apple Music, JioSaavn, or Amazon Music URLs as playback routes. Those are metadata provenance only.
2. **Fail closed.** If a YouTube video's actual runtime or content does not clearly match the catalog record, do not attach it. Leave `youtubeId: null`.
3. **One continuous upload = one playable item.** A 30-chapter nonstop set counts as one set route, not 30 song routes. Chapter timestamps inside that set are song-level routes only if the label published them.
4. **Prefer individual Topic uploads** (auto-generated by YouTube from official distributor data) over unofficial re-uploads.
5. **Do not reuse a video ID already assigned to another release.** Check `grep -r "VIDEO_ID" data/` before assigning.
6. **Read RAAS first.** Before touching any file, read `.raas/RAAS.md`, `.raas/PROJECT-CONTEXT.md`, and `.raas/EXECUTION.md`.

## How to wire a link

### For a single-song upload (most common for modern releases)

In the relevant `data/catalogue/songs/songs-*.json`, set:
```json
"youtubeId": "VIDEO_ID",
"audioAvailability": "youtube-official"
```

Then add to `data/playback-sources-current.json` under `"songSources"`:
```json
"SONG_ID": {
  "provider": "youtube",
  "videoId": "VIDEO_ID",
  "startSeconds": 0,
  "sourceUrl": "https://www.youtube.com/watch?v=VIDEO_ID",
  "sourceType": "youtube-topic",
  "releaseId": "RELEASE_ID",
  "trackNumber": N,
  "evidenceType": "individual-song-topic-upload"
}
```

### For a chapter-timestamped route inside a set

Same as above but with `"startSeconds": OFFSET` and `"evidenceType": "provider-published-official-chapter"`.

### After every batch of changes

```bash
npm run catalogue
npm run check
git add -A && git commit -m "feat(playback): link [RELEASE] song-level YouTube routes"
```
